## 1. 产品概述

### 1.1 背景
现有官网（TECH.md）是零依赖静态站，文案写死在 HTML 与 frontmatter，改内容必须动源码 + `npm run sync`。本期建设一套**独立、自托管、容器化的 CMS**，让市场 / 运营自助维护内容。

### 1.2 技术架构总览
```
┌────────────────────────────┐         ┌──────────────────────────────────────┐
│  Vue 3 控制台 (浏览器)      │  HTTPS  │  Docker 容器：cms-backend (Spring Boot)│
│  - 登录 / 编辑 / 预览       │ ──────▶ │  - 认证 (Spring Security+JWT)         │
│  - 发布 / 历史回滚          │  JSON   │  - 内容 CRUD + 版本管理               │
└────────────────────────────┘         │  - 发布服务 → 触发静态站重建           │
                                        └──────────────┬───────────────────────┘
                                                       │ JPA / JDBC
                              Docker 容器：cms-db (PostgreSQL)│
                                                       ▼
                                              ┌────────────────────┐
                                              │   cms_db 卷（持久化）│
                                              │  users / documents  │
                                              │  revisions / media  │
                                              └────────────────────┘
                                                       │ 发布后
                                                       ▼
                              静态站构建 (build.mjs --cms) 拉取已发布内容
                                                       │
                                                       ▼
                                  GitHub Pages / Vercel（公开官网，与现状一致）
```
> 控制台静态资源由 `cms-console`（nginx 镜像）托管，与后端同属 `docker compose` 编排；公开官网不在 compose 内，仍走现有 Pages / Vercel。

### 1.3 建设目标
- 内容**单一数据源在 PostgreSQL**，编辑、预览、发布、回滚全在控制台完成。
- 登录用 **CMS 自身账号**，与 GitHub 解耦；支持多运营账号与角色。
- 公开官网保持**纯静态、零运行时依赖**（沿用现有 Pages / Vercel 部署），内容在**构建时**从 CMS 拉取。
- **CMS 自身（后端 + 数据库 + 控制台）以 Docker 容器交付**：一条 `docker compose up` 起整套，便于在同配置环境复现、迁移与回滚。

## 2. 用户角色与权限（CMS 自身账号）

账号存于 PostgreSQL `cms_users` 表，由 CMS 自己管理，与 GitHub 无关。

| 角色 | 权限 | 典型动作 |
| --- | --- | --- |
| **超级管理员 (SUPER_ADMIN)** | 全部权限 + 账号管理 + 系统设置 | 创建编辑账号、配置部署令牌、查看审计 |
| **内容编辑 (EDITOR)** | 内容读 / 写 / 发布 / 回滚 | 改首页、加案例、发布 |
| **只读 (VIEWER)** | 仅查看内容与历史 | 审核预览，不能发布 |

- 首次启动由环境变量种子一个管理员（`CMS_ADMIN_USER` / `CMS_ADMIN_PASS`），强制首次登录改密。
- 密码 BCrypt 哈希；登录发放 JWT（短期 access + 可选 refresh）。
- 接口全部需鉴权（除登录），基于角色做方法级授权。

## 3. 控制台信息架构（Vue 3 SPA）

```
CMS 控制台
├─ 登录（CMS 账号）
├─ 仪表盘：六内容区状态（最近更新 / 待发布改动 / 编辑人）
├─ 站点设置
│   ├─ 品牌（名称、Slogan、Logo 文字）
│   ├─ 联系（业务邮箱、地址、预约表单收件邮箱）
│   ├─ 页脚（版权年份、ICP 备案号、公网安备号）
│   ├─ 导航栏（5 栏目名称与链接）
│   └─ SEO 默认（站点标题、描述）
├─ 页面内容
│   ├─ 首页 / 产品能力 / 行业方案 / 客户案例 / 关于我们
├─ 发布与历史
│   ├─ 本次改动预览
│   ├─ 发布（标记已发布 → 触发静态站重建）
│   └─ 历史版本（查看 / 回滚）
└─ 系统（账号管理、部署令牌、审计日志）— 仅 SUPER_ADMIN
```

## 4. 内容模型

内容以「文档（document）」为单位存 PostgreSQL，每个文档为一段 JSONB：
`site` / `home` / `product` / `solutions` / `cases` / `about`。字段与 v0.2 §4 完全相同：

- **site**：品牌、联系（邮箱 / 地址 / 表单收件）、页脚（版权 / ICP / 安备）、导航、SEO 默认。
- **home**：hero / 数据条 / 痛点 / Agent 矩阵 / 交付步骤 / 架构 / 证言 / Logo 墙。
- **product**：hero + 4 个能力模块（标题 / 描述 / 要点列表）。
- **solutions**：hero + 4 个行业卡（场景 / 价值点）。
- **cases**：hero + 3 个案例卡（行业 / 挑战 / 方案 / 量化指标）。
- **about**：hero / 简介 / 数据格 / 价值观 / 联系区。

> 每页 **SEO 三元组（title / description / nav 高亮键）** 一并纳入对应文档的 `meta` 字段。
> 纯文字与列表数据全部可改；**CSS 模拟图、SVG 图标、页面布局结构保持代码侧不变**。

## 5. 控制台功能需求

### 5.1 认证与进入
- 独立登录页（CMS 账号），JWT 鉴权；未登录无法读取 / 写入任何内容。
- Token 过期自动跳登录；支持退出。

### 5.2 仪表盘
- 六张内容区状态卡：最近更新时间、编辑人、是否有未发布改动（与已发布版本 diff）。

### 5.3 编辑器（Schema 驱动）
- 后端提供内容 schema（字段类型 / 必填 / 长度 / 是否列表），Vue 前端据此**动态渲染表单**：文本框、多行文本、可增删列表项、数字 + 后缀。
- 列表项支持上移 / 下移 / 删除 / 新增。
- 敏感占位（备案号、邮箱）高亮「上线前需替换」。

### 5.4 预览
- 右侧实时渲染该区块在**真实线上样式**下的效果（前端按线上 CSS 套用内容），不发布也能看。

### 5.5 发布（核心）
- 「保存」= 写入草稿（`documents` 表，仅自己可见）。
- 「发布」= 标记该文档为已发布（生成一条 `revisions` 快照）→ 调用发布服务 → 触发公开站重建（见 TECH §5）。
- 发布后控制台显示「已发布，预计 1–2 分钟生效」。

### 5.6 历史与回滚
- 每次发布生成 `revisions` 记录（时间 / 操作人 / 摘要）。
- 可查看任意历史版本内容、可一键回滚（等于再发布一次该快照）。

### 5.7 校验与防护
- 必填、邮箱 / 手机号格式、长度校验（依据 schema）。
- 发布前对文案做 HTML 转义，防止误写标签破坏布局。
- 发布只改数据库内容，**绝不动 `src/` 模板与 `build.mjs`**；构建仍由独立流程执行。

## 6. 设计语言

- 后台管理风：深色科技感，与官网一致（底色 `#060912`、品牌蓝紫 `#3B7BFF / #8B5CF6`、文字 `#F2F5FF / #97A3C0`）。
- 基于 **Element Plus** 组件库（表格 / 表单 / 对话框 / 消息），中文文档完善、出活快。
- 布局：左侧导航 + 右侧编辑 / 预览双栏；移动端折叠单栏。
- 字体：系统中文栈。

---

## 7. 非功能需求

- **安全**：JWT 短时效 + BCrypt；RBAC 方法级控制；CORS 仅放行控制台域名；密码不落日志；部署令牌独立、可吊销。
- **性能**：公开站仍纯静态、首屏无图片请求；控制台 SPA 走 Vite 构建、按需加载。
- **可靠**：发布采用「先写库快照、再触发构建」的原子思路；构建失败不影响已上线版本。
- **可维护**：内容 schema 集中定义；字段变更只需改 schema + 对应模板占位。
- **可移植 / 交付**：CMS 整栈以 Docker 交付，`docker compose up` 即可在同配置环境复现；敏感配置走 `.env` / Secret，不进镜像与代码仓库；数据库用命名卷持久化，容器重建不丢数据。

## 8. 验收标准

1. 运营用 CMS 账号登录后，可不经源码完成：改首页 Hero、增删客户案例、改页脚备案号。
2. 点「发布」后 1–2 分钟内，线上官网（Pages / Vercel）显示新内容。
3. 控制台预览与实际线上渲染一致（同套 CSS）。
4. 历史可查、可回滚到任意已发布版本。
5. 发布操作只改 PostgreSQL 内容，不触碰 `src/` 与 `build.mjs`；构建无残留 `{{变量}}`。
6. 未登录无法读写；CMS 账号与 GitHub 完全解耦；密码为哈希存储。
7. **CMS 通过 `docker compose up` 启动后端 + 数据库 + 控制台，数据持久化、重启不丢；配置均来自 `.env`，镜像可直接迁移到新机器。**

## 9. 范围边界

**v1 包含**：文字与列表数据可视化编辑 / 预览 / 发布 / 历史回滚；CMS 自身多账号与角色；六页内容模型；Docker 容器化交付与运行。

**v1 不含**：真实图片 / 素材上传管理（当前站点纯 CSS 模拟图，无图可管）；多语言；富文本编辑器（v1 用纯文本 / 多行文本）；A/B 与埋点；细粒度字段级权限；Kubernetes 编排（v1 用单 `docker compose`，集群编排留待后续）。

## 10. 与现有站点的衔接

- 实现阶段把 `src/pages/*.html` 文案替换为 `{{content.*}}` 占位，与 v0.2 模板改造一致。
- `build.mjs` 增加 `--cms` 模式：调用 CMS「获取已发布内容」接口（带部署令牌）拉取全部文档 JSON，再按点号路径变量渲染（详见 TECH §5）。
- 开发者仍可用 `npm run sync` 以本地 `content/*.json` 兜底构建；生产发布走 CMS（容器内运行）→ 数据库 → 重建。
- 公开官网部署（Pages / Vercel）不在 compose 内，仍由发布钩子触发独立构建。
