# 乾腾元官网 · 产品需求文档（PRD）

> 版本：v1.0 ｜ 日期：2026-09-03 ｜ 状态：已交付 · 评审中 ｜ 关联设计稿：Ardot `fileId 721718316795995`（桌面 5 页 + 移动 5 页）
> 适用范围：本 PRD 描述官网**当前已交付版本**的功能与设计约定，作为后续迭代与验收的基准。

---

## 1. 产品概述

### 1.1 背景
杭州乾腾元科技有限公司（品牌名 QTY AI）定位为「企业级 AI Agent 全栈服务商」，需要一处对外窗口，向潜在企业客户讲清「做什么、怎么帮客户落地、有哪些证明」。此前缺乏统一、专业的官网，销售与品牌物料分散。

### 1.2 产品定位
面向企业决策者的**品牌官网 + 能力展示 + 线索收集**入口。不承载复杂交易或登录态，核心是「讲清楚能力 → 建立信任 → 引导预约」。

### 1.3 建设目标
- 建立专业、可信的科技品牌形象（深色科技感 + 蓝紫辉光）。
- 让访客在 15 秒内理解「乾腾元 = 企业级 AI Agent 全栈服务商」。
- 覆盖六大核心页面，结构完整、移动端可用。
- 提供明确的转化路径（预约演示 / 业务咨询）。

---

## 2. 目标用户与使用场景

| 用户角色 | 核心诉求 | 关键页面 |
| --- | --- | --- |
| 企业 CTO / 技术负责人 | 评估 Agent 平台能力与落地路径 | 产品能力、行业解决方案 |
| 业务负责人 / 数字化负责人 | 找同行业标杆案例与 ROI | 客户案例、行业解决方案 |
| 采购 / 决策者 | 公司实力、资质、联系方式 | 关于我们 |
| 投资人 / 合作伙伴 | 公司定位、团队、愿景 | 关于我们、首页 |

**典型路径**：首页（建立认知）→ 产品能力（理解产品）→ 客户案例（建立信任）→ 关于我们（联系方式）→ 提交预约。

---

## 3. 核心指标（成功标准）

- **认知效率**：首页首屏在 15 秒内传达核心定位（首屏含主标题 + 副标题 + 双 CTA）。
- **转化可用**：每个核心页面底部均有「预约演示 / 咨询」入口，表单可成功提交。
- **可达性**：全站 6 个页面 + 404 均可访问，移动端单列可读。
- **性能**：纯静态、零运行时依赖，首屏无图片请求（占位图用 CSS/HTML 模拟）。
- **SEO 基线**：每页独立 title / description / canonical，含 sitemap 与 robots。

## 4. 信息架构

```
乾腾元官网
├─ 首页（/）
├─ 产品能力（/product.html）
```

> 说明：导航中已**移除**「登录控制台」入口（本期不涉及用户登录体系）。

## 5. 页面需求详述

### 5.1 首页（/）
- **Hero**：主标题 + 副标题 + 双 CTA（预约演示 / 了解能力）+ 右侧控制台视觉（CSS 模拟）。
- **数据条**：4 项核心指标（如 320+ 企业服务、80+ 行业模板、42% 平均效率提升、15 天平均上线）。
- **痛点区**：企业落地 AI Agent 的常见障碍。
- **能力矩阵**：6 张能力卡（多 Agent 编排 / 知识库 / 连接器 / 安全合规 / 监控运维 / 低代码）。
- **流程区**：从需求到上线的标准路径。
- **架构图**：平台技术架构分层示意。
- **客户证言 / 合作伙伴 Logo 墙**。
- **CTA 区**。

### 5.2 产品能力（/product.html）
- Hero + 4 个 Feature Block（能力模块），每块含标题、说明、要点列表、CSS 模拟界面插图。
- 复用全局 CTA 区。

### 5.3 行业解决方案（/solutions.html）
- Hero + 解决方案网格（4 个行业卡：制造 / 金融 / 零售 / 医疗政务，卡片含场景描述与价值点）。
- 复用全局 CTA 区。

### 5.4 客户案例（/cases.html）
- Hero + 3 个案例卡（交替左右布局，含客户行业、挑战、方案、量化收益指标）。
- 复用全局 CTA 区。

### 5.5 关于我们（/about.html）
- Hero + 公司简介 + 核心数据格（成立年份 / 团队规模 / 服务客户 / 客户满意度）+ 价值观 3 卡。
- **联系区**：业务咨询信息 + 预约表单（见第 6.5 节）。

### 5.6 404 页面（/404.html）
- 简洁的「页面不存在」提示 + 返回首页入口。

## 6. 全局功能需求

### 6.1 导航
- 桌面端横向展示 5 个栏目，当前页高亮（构建时注入 `data-active`）。
- 移动端（≤768px）折叠为汉堡抽屉，打开时锁定 body 滚动。
- 平滑锚点滚动，滚动时导航吸顶并带毛玻璃。

### 6.2 页脚
- 满宽铺开（与 1200 内容区对齐），品牌区与链接列整体左对齐分栏。
- 含业务邮箱 `hi@qtysoft-ai.com` 与地址占位，底栏含版权与 ICP 备案号占位。

### 6.3 响应式
- 桌面设计稿基准 1440，移动基准 375。
- 字号线性收敛：H1 `clamp(33px, 5.2vw, 62px)`、H2 `clamp(25px, 3.2vw, 40px)`。
- 多列网格在移动端降为单列，数据格降为 2 列，导航转抽屉，底部加吸底咨询条。

### 6.4 SEO 与社交分享
- 每页独立 `<title>` / `<meta name="description">` / canonical。
- OG 卡片（og-cover.svg）、Twitter Card、Organization JSON-LD。
- `sitemap.xml`（构建时自动生成）+ `robots.txt`。

### 6.5 预约表单（关于我们页）
- 字段：公司名称、联系人、联系方式、意向场景、留言。
- 前端校验（必填、手机号/邮箱格式），错误就近内联提示。
- 提交行为：**调起访客邮件客户端，生成一封发往 `coolxuhanbing@gmail.com` 的草稿**（含全部填写内容 + 提交时间）。收件人写在 `<form data-email="...">`，改一处即可。
- 提交成功/失败均有状态提示。

> 注意：当前为 `mailto:` 起草方案，依赖访客本机已配置邮件客户端。真·自动发送需接第三方服务（见技术文档 §10）。

### 6.6 性能与可访问性基线
- 使用系统字体栈，不加载中文字体包。
- `prefers-reduced-motion` 下关闭动效。
- 可见焦点环、skip-link、语义化标签、对比度达标。

## 7. 设计语言与规范

| 维度 | 约定 |
| --- | --- |
| 视觉风格 | 深色科技感，蓝紫辉光，渐变文字标题 |
| 内容栅格 | 容器最大宽 1200px，左右安全边距 24px |
| 底色层次 | `--bg #060912` / `--bg-alt` / `--surface #0C1425` 等 |
| 品牌色 | `--brand #3B7BFF` / `--violet #8B5CF6` / `--cyan #22D3EE` |
| 文字色 | `--text #F2F5FF` / `--text-2 #97A3C0` 等 |
| 圆角 | 6 / 10 / 14 / 20 / 28 / 999(pill) |
| 字体 | 系统中文字体栈（PingFang SC / Noto Sans SC 优先） |
| 动效 | `cubic-bezier(.4,0,.2,1)`，默认时长 .28s，滚动进场 .6s |

完整令牌见技术文档 §6 与 `src/assets/css/tokens.css`。

## 8. 非功能性需求

- **浏览器兼容**：主流现代浏览器（Chrome / Edge / Safari / Firefox 近两个大版本）。
- **可用性**：关键任务（浏览、找到联系方式、提交表单）无需登录。
- **可维护性**：设计令牌集中、页面片段复用、域名/邮箱为单一变量，改一处全站生效。

---

## 9. 验收标准

1. 6 个页面路由均可访问（HTTP 200），内容与设计稿一致。
2. 桌面与移动端布局均正常，无溢出、无重叠、无裁切。
3. 导航当前页高亮正确，移动端抽屉可开合。
4. 预约表单校验与提交（mailto 起草）行为符合 §6.5。
5. 每页 SEO 元信息、sitemap、robots 正确生成。
6. 全站无占位符残留、无控制台报错、无未替换的 `{{变量}}`。
